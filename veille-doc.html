04 — Veille · Documentation technique

Veille automatisée

Comment la page Veille de ce portfolio se met à jour seule chaque matin à partir de flux RSS, sans serveur à administrer et sans coût.

1. Contexte 2. Architecture 3. Prérequis 4. Sources 5. Script 6. Mise en place 7. Tests 8. Sécurité 9. Maintenance 10. Compétences

1. Contexte et objectifs

La page Veille du portfolio se met à jour seule chaque matin à partir de flux RSS, sans serveur à administrer et sans coût. Cette réalisation s'inscrit dans le BTS SIO option SISR (EnsiTech Saint-Herblain, 2025–2027).

Besoin. Le portfolio présente une veille sur deux thèmes : les matériels réseau et les cyberattaques en France. Mise à jour à la main, elle vieillit vite et le jury voit tout de suite une veille figée.

Objectifs.

  • Afficher chaque jour les articles récents de sources fiables, triés par date.
  • Garder séparées l'actualité automatique et l'analyse personnelle (cartes « Mon analyse »).
  • Utiliser uniquement des outils gratuits : GitHub, GitHub Actions, GitHub Pages, Python.
  • Ne rien casser si une source ne répond pas.

Périmètre. Le script ne rédige aucune analyse : il collecte et met en forme. La synthèse reste un travail personnel, mis à jour à la main.

2. Architecture de la solution

La solution repose entièrement sur GitHub : une planification déclenche un script Python, qui réécrit la page et la republie. Aucun serveur n'est à installer ni à maintenir.

Le dépôt GitHub sert à la fois de stockage du code, de moteur d'exécution (Actions) et d'hébergement (Pages). Les fichiers concernés : scripts/update_veille.py, .github/workflows/veille.yml et veille.html.

4. Choix des sources

Les sources ont été retenues pour leur fiabilité, leur fréquence de publication et la disponibilité d'un flux RSS ou Atom public. Les sources généralistes passent par un filtre de mots-clés pour ne garder que le thème de l'onglet.

Critères de sélection des articles.

  • Publiés depuis moins de 45 jours.
  • 3 articles au maximum par source, pour qu'une source très active n'occupe pas tout l'onglet.
  • 6 articles au maximum par onglet, triés du plus récent au plus ancien.
  • Doublons supprimés (même lien publié par deux flux).

Mots-clés réseau (extrait) : réseau, Wi-Fi, routeur, switch, Cisco, Fortinet, pfSense, VLAN, SD-WAN, 5G, VPN, pare-feu, DNS, IPv6, BGP.

Mots-clés cybersécurité (extrait) : cyber, vulnérabilité, CVE, ransomware, rançongiciel, phishing, fuite, faille, attaque, ANSSI, MFA.

5. Fonctionnement du script update_veille.py

Le script lit chaque flux, garde les articles qui respectent les critères, puis réécrit uniquement la zone balisée de veille.html. Le reste de la page n'est jamais touché.

  1. Téléchargement : urllib.request récupère chaque flux avec un délai maximal de 20 secondes. En cas d'erreur, la source est ignorée et un message s'affiche dans le journal.
  2. Analyse XML : xml.etree.ElementTree lit les deux formats existants, RSS 2.0 (balises <item>) et Atom (balises <entry>).
  3. Nettoyage : les balises HTML des résumés sont retirées et le texte est coupé à 220 caractères.
  4. Filtrage : âge maximal, mots-clés pour les sources marquées filtre: True, limite par source, doublons.
  5. Génération HTML : chaque article devient un élément de liste (source, date, titre cliquable, résumé). Tous les textes passent par html.escape avant d'être insérés.
  6. Remplacement : une expression régulière remplace le contenu situé entre les marqueurs de la page.

Les marqueurs délimitent la zone que le script a le droit de modifier :

<!-- VEILLE-AUTO:cyber:START -->
  ... contenu généré automatiquement ...
<!-- VEILLE-AUTO:cyber:END -->

La configuration se trouve en tête du script, ce qui permet d'ajouter une source sans toucher au reste du code :

SOURCES = {
    "cyber": [
        {"nom": "CERT-FR alertes",
         "url": "https://www.cert.ssi.gouv.fr/alerte/feed/",
         "filtre": False},
        # ...
    ],
}
MAX_ARTICLES = 6
MAX_PAR_SOURCE = 3
MAX_AGE_JOURS = 45

Si aucun article n'est trouvé pour un thème, le bloc existant est conservé tel quel au lieu d'être vidé.

6. Procédure de mise en place

La mise en place prend une quinzaine de minutes et ne se fait qu'une fois.

  1. Créer le dépôt : sur GitHub, New repository, visibilité Public.
  2. Envoyer les fichiers : les pages HTML, style.css, script.js, scripts/update_veille.py et .github/workflows/veille.yml. Le dossier .github est caché sur la plupart des systèmes : vérifier qu'il est bien présent dans le dépôt.
  3. Activer GitHub Pages : Settings → Pages, source Deploy from a branch, branche main, dossier / (root).
  4. Autoriser l'écriture : Settings → Actions → General → Workflow permissions, cocher Read and write permissions. Sans ce réglage, l'Action ne peut pas enregistrer la page mise à jour.
  5. Premier lancement : onglet Actions, workflow « Mise à jour de la veille », bouton Run workflow.
  6. Vérifier : le journal liste le nombre d'articles par source, un commit « Veille : mise à jour automatique du … » apparaît, puis la page Veille du site affiche les articles une à deux minutes plus tard.

Le workflow veille.yml se déclenche de deux façons :

on:
  schedule:
    - cron: "23 5 * * *"   # chaque jour à 5h23 UTC (6h23 à Paris en hiver)
  workflow_dispatch:        # lancement manuel

permissions:
  contents: write          # nécessaire pour faire le commit

La dernière étape du workflow ne fait un commit que si veille.html a réellement changé (git diff --quiet). L'historique du dépôt ne se remplit donc pas de commits vides.

  • Second lancement le même jour sans nouvel article : aucun commit

  • Affichage correct sur téléphone

8. Sécurité

Le contenu des flux vient de sites tiers. Il est donc traité comme non fiable, et les droits de l'automatisation sont limités au strict nécessaire.

RisqueMesure appliquée
Injection de code (XSS) via un titre ou un résumé piégéBalises HTML retirées, puis tout le texte échappé avec html.escape avant insertion
Lien malveillant (javascript:…)Seuls les liens commençant par http sont conservés
Droits trop larges de l'ActionPermission limitée à contents: write, aucun secret ni mot de passe stocké
Modification de toute la pageÉcriture limitée à la zone entre les marqueurs VEILLE-AUTO
Ouverture d'un lien externeAttributs target="_blank" et rel="noopener" sur chaque lien
Source compromise ou en panneUne erreur sur une source n'interrompt pas les autres ; la source peut être retirée de la liste en une ligne

9. Maintenance, dépannage et évolutions

Maintenance courante.

  • Chaque semaine, relire le fil et mettre à jour les cartes « Mon analyse » avec les sujets marquants.
  • Ajouter ou retirer une source : modifier la liste SOURCES en tête du script, puis relancer le workflow.
  • Ajuster les mots-clés si trop d'articles hors sujet passent le filtre, ou trop peu d'articles le traversent.
  • Ne jamais modifier à la main le contenu situé entre les marqueurs : il est écrasé au passage suivant.

Dépannage.

SymptômeCause probableSolution
Workflow en rouge à l'étape « Publier »Permission d'écriture absenteSettings → Actions → General, cocher Read and write permissions
Une source affiche 0 articleFlux déplacé, en panne ou filtre trop strictOuvrir l'URL du flux dans un navigateur, la corriger ou retirer la source
Message « Marqueurs introuvables »Marqueurs supprimés de veille.htmlRemettre les deux lignes VEILLE-AUTO de l'onglet concerné
Plus aucune mise à jour automatiquePlanification suspendue par GitHub après une longue inactivité du dépôtOnglet Actions, réactiver le workflow
Page en ligne inchangée malgré le commitPublication GitHub Pages en cours ou en échecVérifier le déploiement pages-build-deployment dans Actions

Évolutions possibles.

  • Ajouter un troisième onglet (par exemple Linux / systèmes, avec LWN.net ou Phoronix).
  • Archiver chaque mois les articles dans un fichier pour garder un historique de la veille.
  • Remplacer les sources par l'export OPML d'un agrégateur auto-hébergé comme FreshRSS.
