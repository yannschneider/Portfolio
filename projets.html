Mes projets

🛡️

pfSense — Firewall & VPN

Pare-feu du siège, DMZ et deux types de VPN

Mise en place d'un pare-feu pfSense CE 2.9 à trois zones (WAN, LAN, DMZ) avec une politique « tout est interdit sauf ce qui est autorisé », la publication d'un serveur web en DMZ, un VPN d'accès distant pour les nomades et un VPN site à site vers une agence.

pfSense CE 2.9 OpenVPN IPsec IKEv2 DMZ NAT PKI
PDFDocumentation d'installation — pfSense, pare-feu et VPN28 pages PDFGuide utilisateur — Travailler à distance avec le VPN9 pages
  • Installation de pfSense CE 2.9 avec le Netgate Installer, interfaces WAN / LAN / DMZ
  • Matrice des flux, alias et règles de filtrage deny-all journalisées
  • Isolement de la DMZ : aucun flux possible vers le LAN
  • Publication du serveur web par redirection de ports (NAT)
  • Résolveur DNS relié à l'Active Directory (zone sisr.lan)
  • Autorité de certification interne, VPN OpenVPN avec certificat et mot de passe
  • Révocation des accès VPN (liste de révocation)
  • VPN IPsec IKEv2 site à site entre le siège et une agence
  • Supervision, sauvegarde chiffrée, cahier de recette de 18 tests

Domaine Active Directory

Annuaire centralisé pour une PME de deux services

Mise en place du domaine sisr.lan sur Windows Server 2022 avec les services DNS et DHCP, organisation de l'annuaire par service, partages avec droits par groupe et stratégies de groupe. Deux postes Windows 11 intégrés au domaine et validés par un cahier de recette.

Windows Server 2022 AD DS GPO DNS DHCP AGDLP
  • Installation de Windows Server 2022 et promotion en contrôleur de domaine
  • Zones DNS (dont recherche inversée), redirecteurs
  • Étendue DHCP et réservations pour les postes clients
  • Unités d'organisation, utilisateurs et groupes selon la méthode AGDLP

  • Jonction de 2 postes Windows 11 Pro, 16 tests de recette validés

GLPI 11 Debian 13 LDAP Apache PHP 8.4 MariaDB

  • Arborescence sécurisée : configuration et données hors de la racine web
  • Publication en HTTPS sur glpi.sisr.lan
  • Authentification Active Directory (LDAP) et attribution automatique des profils
  • Inventaire automatique des postes avec GLPI Agent
  • Sauvegarde et restauration, cahier de recette
  • Guide utilisateur pour les utilisateurs, techniciens et administrateurs

Veille technologique automatisée

Réseau et cybersécurité, mise à jour chaque matin

Veille sur les matériels réseau et les cyberattaques en France, publiée sur ce portfolio. Un script Python lancé chaque jour par GitHub Actions lit les flux RSS de sources fiables (CERT-FR, ZATAZ, IT-Connect…) et met à jour la page tout seul. Mes analyses personnelles complètent ce fil d'actualité.

Python GitHub Actions RSS / Atom GitHub Pages CERT-FR Git
WEBPage Veille — actualités et analysesMatériels réseau · Cyberattaques France WEBDocumentation technique — Veille automatiséeArchitecture · procédure · tests · sécurité
  • Méthode régulière : survol quotidien du fil, analyse approfondie chaque semaine, flux organisés dans un agrégateur (OPML)
  • Choix de 7 sources selon leur fiabilité : CERT-FR, ZATAZ, IT-Connect, Le Monde Informatique, Network World
  • Script Python sans dépendance : lecture des flux RSS et Atom, filtrage par mots-clés, tri et dédoublonnage
  • Planification quotidienne avec GitHub Actions et publication automatique sur GitHub Pages
  • Sécurité : échappement du contenu externe (XSS), liens filtrés, droits limités du workflow
  • Tests avec des flux d'essai : RSS, Atom, source en panne, article hors sujet, caractères spéciaux
  • Analyses personnelles : Wi-Fi 7 et 8, réseaux d'entreprise, ransomware, NIS 2 et Cyber Resilience Act
  • Documentation technique publiée sur le portfolio

PROJET 08 — Supervision & Sécurité

Sonde de supervision sous Kali Linux

Disponibilité, inventaire et détection d'intrusion du réseau local

Sonde virtuelle construite à partir de l'ISO Kali Linux 2026.3 : installation entièrement automatisée, outils de Kali (nmap, tcpdump, Wireshark) complétés par Suricata, Prometheus, Grafana, darkstat, arpwatch et vnStat. Elle surveille la box, le DNS et Internet, inventorie les appareils, détecte les balayages et alerte en moins de trois minutes. Recette de 20 tests, tous validés.

Kali Linux Suricata Prometheus Grafana nmap nftables VirtualBox
PDFDocumentation d'installation — Sonde de supervision Kali24 pages PDFGuide utilisateur — Surveiller son réseau avec la sonde13 pages CODEScripts et fichiers de configurationpreseed · provisionnement · recette
  • Installation de Kali sans intervention par fichier preseed servi en HTTP, compte et clé SSH déposés automatiquement
  • VM à deux cartes : NAT pour l'administration, pont sur le réseau surveillé
  • Suricata avec 53 600 règles Emerging Threats et des règles locales (balayages, protocoles en clair)
  • Prometheus et blackbox_exporter : ping, DNS et HTTP toutes les 30 s, 10 règles d'alerte
  • Découverte nmap toutes les 15 min, inventaire horodaté des appareils, arpwatch
  • Tableau de bord Grafana provisionné par fichiers, trafic par appareil avec darkstat
  • Pare-feu nftables : aucun service exposé sur le réseau, adresses MAC minimisées (RGPD)
  • Sauvegarde quotidienne testée, planning, indicateurs et analyse des écarts, recette 20/20

PROJET 09 — Cybersécurité
🔐

Durcissement d'un serveur Linux

Sécuriser un serveur Debian avant sa mise en production

Une PME installe un serveur Debian 13 pour ses services internes. Avant la mise en production, j'ai réduit sa surface d'attaque : compte d'administration dédié, politique de mots de passe, SSH par clé uniquement, pare-feu, fail2ban et mises à jour automatiques. Chaque mesure a été vérifiée depuis un second poste, puis le résultat mesuré avec un audit Lynis.

Debian 13 OpenSSH ufw fail2ban PAM Lynis VirtualBox
PDFDocumentation d'installation — Durcissement du serveur29 pages PDFGuide d'exploitation — Administrer le serveur durci10 pages
  • Maquette VirtualBox : serveur Debian 13 et poste client sur un réseau isolé, instantané avant durcissement
  • Partitions /home, /var et /tmp séparées, compte root verrouillé
  • Compte d'administration sudo dédié, politique de mots de passe (pam_pwquality)
  • Verrouillage du compte après 5 échecs (pam_faillock)
  • SSH par clé ED25519 uniquement : root et mots de passe refusés, AllowUsers
  • Pare-feu ufw en refus par défaut, seul SSH autorisé
  • fail2ban : bannissement après 3 échecs, testé par une attaque simulée
  • Mises à jour de sécurité automatiques, services inutiles désactivés
  • Audit Lynis (indice 70/100), tests rejoués après redémarrage
